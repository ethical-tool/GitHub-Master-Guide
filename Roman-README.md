# 1. GitHub Introduction

GitHub aik cloud-based development platform hai jo Git version control system use karta hai.

GitHub ki madad se aap:

- Projects online host kar sakte hain.
- Source code share kar sakte hain.
- Project ki history maintain kar sakte hain.
- Team ke saath collaborate kar sakte hain.
- Open-source projects mein contribute kar sakte hain.
- Bugs report kar sakte hain.
- Software releases publish kar sakte hain.
- Automated testing aur deployment kar sakte hain.
- Apna professional developer portfolio bana sakte hain.

**Official Website:**

https://github.com/

**Official Documentation:**

https://docs.github.com/

# 2. Git Aur GitHub Mein Farq

### Git

Git aik distributed version control system hai.

Is ka kaam:

- Code changes track karna.
- Commits create karna.
- Branches manage karna.
- Previous versions restore karna.
- Different developers ke changes merge karna.

### GitHub

GitHub aik online platform hai jo Git repositories ko host karta hai.

Is mein additional features hain:

- Pull Requests.
- Issues.
- Discussions.
- Actions.
- Releases.
- Projects.
- Security alerts.

Git local computer par bhi kaam karta hai, jabke GitHub online collaboration provide karta hai.

Official Git:

https://git-scm.com/

# 4. Account Security

Apne GitHub account ko secure rakhna bohat zaroori hai.

- Two-Factor Authentication enable karein.

- Unknown SSH keys remove karein.
- Unknown Personal Access Tokens revoke karein.

- Account recovery email secure rakhein.
- Public computer par account logout karein.

### Two-Factor Authentication

2FA account security ki additional layer hai.

Is mein password ke ilawa aik second verification method bhi required hota hai.

# 8. Public vs Private

### Public Repository

Public repository ko internet users dekh sakte hain.

Features:

- Public visibility.
- GitHub users fork kar sakte hain.
- Stars aur watchers mil sakte hain.
- Contributions receive kar sakte hain.
- Open-source projects publish kar sakte hain.

### Private Repository

Private repository sirf authorized users ke liye hoti hai.

Features:

- Restricted access.
- Team collaboration.
- Private development.
- Access permissions control.

### Important

Public repository ka matlab ye nahi ke har user ko aapke content ko kisi bhi tareeqe se reuse karne ki legal permission mil gayi hai.

License aur GitHub Terms dono ko samajhna zaroori hai.

# 14. Complete License Guide

License aik legal document hota hai jo define karta hai ke doosre developers aapke project ko kis tarah use, modify aur distribute kar sakte hain.

License ke baghair default copyright rules apply hote hain.

GitHub par available common license options ki examples:

### 14.1 MIT License

MIT aik permissive open-source license hai.

Permissions:

- Commercial use.
- Modification.
- Distribution.
- Private use.
- Sublicensing.

Conditions:

- Copyright notice preserve karna.
- License notice include karna.

MIT modified software ko open-source rakhna lazmi nahi banata.

https://opensource.org/license/mit

### 14.2 Apache License 2.0

Apache 2.0 aik permissive license hai.

Features:

- Commercial use allowed.
- Modification allowed.
- Distribution allowed.
- Patent license provisions.
- Copyright notices preserve karna.
- Changes ke notices ki requirements.

https://www.apache.org/licenses/LICENSE-2.0

### 14.3 GNU GPL v2.0

GPL v2 aik copyleft license hai.

Features:

- Software use kar sakte hain.
- Modify kar sakte hain.
- Distribute kar sakte hain.
- Covered modified versions distribute karte waqt GPL v2 ki conditions follow karni hoti hain.
- Applicable source code requirements follow karni hoti hain.

https://www.gnu.org/licenses/old-licenses/gpl-2.0.html

### 14.4 GNU GPL v3.0

GPL v3 aik strong copyleft open-source license hai.

Features:

- Software use kar sakte hain.
- Source code modify kar sakte hain.
- Copies distribute kar sakte hain.
- Commercial distribution allowed hai.
- Covered modified versions distribute karte waqt GPL v3 follow karna hota hai.
- Applicable source code provide karne ki conditions hoti hain.
- Patent aur anti-tivoization provisions bhi hain.

**Important:** GPL v3 copy aur modification ko ban nahi karta. Ye permissions deta hai, lekin redistribution aur modified versions par specific conditions lagata hai.

https://www.gnu.org/licenses/gpl-3.0.en.html

### 14.5 GNU LGPL

LGPL library-oriented copyleft license hai.

Is ka purpose libraries ko doosre software ke saath use karne ki flexibility dena hai.

LGPL ki apni linking, modification aur distribution conditions hoti hain.

https://www.gnu.org/licenses/lgpl-3.0.en.html

### 14.6 GNU AGPL v3

AGPL v3 network-based software ke liye additional copyleft requirements rakhta hai.

Agar covered modified software ko network ke zariye users interact karte hain, to source code offer ki requirements apply ho sakti hain.

https://www.gnu.org/licenses/agpl-3.0.en.html

### 14.7 BSD 2-Clause

Ye permissive license hai.

- Commercial use.
- Modification.
- Distribution.
- Copyright aur license notice preserve karna.

https://opensource.org/license/bsd-2-clause

### 14.8 BSD 3-Clause

BSD 2-Clause ki tarah permissive hai, lekin is mein original contributors ke naam ko endorsement ke liye bina permission use karne par restriction bhi hoti hai.

https://opensource.org/license/bsd-3-clause

### 14.9 ISC License

ISC aik simple permissive license hai.

- Use allowed.
- Modification allowed.
- Distribution allowed.
- Copyright aur permission notice preserve karna.

https://opensource.org/license/isc-license-txt

### 14.10 Mozilla Public License 2.0

MPL 2.0 file-level copyleft license hai.

Covered files mein modifications distribute karte waqt MPL ki conditions follow karni hoti hain.

https://www.mozilla.org/en-US/MPL/2.0/

### 14.11 Creative Commons Licenses

Creative Commons licenses zyada tar documentation, articles, educational content, images aur other creative works ke liye use hoti hain.

Common options:

- CC BY: Attribution required.
- CC BY-SA: Attribution aur same-license sharing.
- CC BY-NC: Non-commercial restrictions.
- CC BY-ND: No derivatives.
- CC0: Public-domain dedication framework.

### 14.12 Unlicense

# 15. GNU GPL v3 Explained

Is repository ka selected license GNU GPL v3.0 hai.

Is ka matlab:

1. Users project ki copies bana sakte hain.
2. Users source code modify kar sakte hain.
3. Users modified versions distribute kar sakte hain.
4. Users commercial purposes ke liye use kar sakte hain.
5. Distribution karte waqt GPL ki applicable conditions follow karni hongi.
6. Covered source code provide karne ki requirements apply hongi.
7. Copyright aur license notices preserve karne honge.

### GPL v3 Kya Allow Nahi Karta?

- Original copyright remove karne ki permission nahi deta.
- License ki conditions ignore karke covered modified software distribute karne ki permission nahi deta.
- GPL-covered work ko bina conditions follow kiye proprietary distribution mein convert karne ki general permission nahi deta.

### Important Clarification

GitHub public repository ko users GitHub Terms ke under fork kar sakte hain.

GPL v3 is se aage ja kar licensed work ke copying, modification aur distribution ke rights aur conditions define karta hai.

Agar tumhara maqsad copying aur modification ko restrict karna hai to GPL v3 us maqsad ke liye suitable nahi hai.

Account flag, restriction aur suspension aik hi cheez nahi hain.

- Content ki visibility restrict ho sakti hai.
- Repository disable ho sakti hai.

# 19. Account Recovery

Agar account restricted ya compromised ho jaye:

### Step 1: Email Check

GitHub ki official email check karein.

Spam aur Junk folders bhi check karein.

### Step 2: Account Security

- Password change karein.
- Unknown sessions aur applications review karein.
- Unknown SSH keys remove karein.
- Personal Access Tokens revoke karein.
- Email account secure karein.
- 2FA enable karein.

### Step 3: Restriction Understand Karein

GitHub ke notification mein di gayi reason samjhein.

### Step 4: Required Changes Karein

Agar content policy violate karta hai to required corrective actions complete karein.

### Step 5: Official Appeal

https://support.github.com/contact/reinstatement

### Step 6: Wait For Review

GitHub ki team appeal review karegi.

Recovery guaranteed nahi hoti.

**Important:** Naya account bana kar suspension bypass karne ki koshish na karein.

# 20. Appeal Process

- Relevant evidence dein.
- Agar account compromised tha to explain karein.

Official Guide:

https://docs.github.com/en/site-policy/acceptable-use-policies/github-appeal-and-reinstatement

# 23. Uploading Large Files

Agar file 100 MiB se bari hai to normal Git ki jagah Git LFS use karein.

Git LFS large files ko separate storage mein rakhta hai aur Git repository mein pointer file maintain karta hai.

Benefits:

- Large binaries manage karna.
- Repository clone ko manageable rakhna.
- Large project assets track karna.
- Version control ke saath files manage karna.

# 24. Git LFS Installation

Ubuntu / Debian:

```bash
sudo apt update

sudo apt install git-lfs
```

Verify:

```bash
git lfs version
```

Initialize:

```bash
git lfs install
```

Official Website:

https://git-lfs.com/

# 25. Uploading 2 GB Files

GitHub Free aur Pro par Git LFS ki maximum individual file size 2 GB hai.

### Step 1: Clone Repository

```bash
git clone https://github.com/USERNAME/REPOSITORY.git

cd REPOSITORY
```

### Step 2: Initialize Git LFS

```bash
git lfs install
```

### Step 3: Track Large Files

```bash
git lfs track "*.zip"
```

Ya aik specific file:

```bash
git lfs track "large-file.zip"
```

### Step 4: Add Attributes

```bash
git add .gitattributes
```

### Step 5: Add File

```bash
git add large-file.zip
```

### Step 6: Commit

```bash
git commit -m "Add large file using Git LFS"
```

### Step 7: Push

```bash
git push origin main
```

### Important

- File 2 GB ki per-file limit se exceed nahi honi chahiye.
- Storage quota check karein.
- Bandwidth quota check karein.
- Stable internet connection use karein.
- Git LFS installed hona chahiye.

Git LFS Billing:

https://docs.github.com/en/billing/concepts/product-billing/git-lfs

# 26. Git Push Limits

GitHub ki single Git push maximum limit 2 GiB hai.

Ye single file ki limit nahi hai.

Agar aik push 2 GiB se bara ho jaye to:

- Push ko smaller commits mein divide karein.
- Smaller batches mein push karein.
- Unnecessary files remove karein.
- Large binaries ke liye Git LFS use karein.

Official Guide:

https://docs.github.com/en/get-started/using-git/troubleshooting-the-2-gb-push-limit

# 27. Repository Size Management

GitHub repositories ko small rakhna recommended hai.

Official recommendation:

- Ideally repository 1 GB se chhoti ho.
- 5 GB se chhoti rakhna strongly recommended hai.

Tips:

- Unnecessary binaries remove karein.
- Temporary files commit na karein.
- Build directories ignore karein.

Is se aap:

- Code quality checks.
- Build automation.
- Deployment.
- Scheduled workflows.
- Release automation.

kar sakte hain.

Example workflow:

```yaml
name: Python Check

on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Check Python
        run: python --version
```

```text
DISCLAIMER:

This project is intended for educational

Users are responsible for their own actions
and compliance with applicable laws.
```

Disclaimer illegal activity ko legal nahi banata. Tool ka actual behavior aur distribution bhi relevant hai.
